02 · 领域模型

六个概念，一条需求线

需求不存进度，由 StageRun 聚合；任务不绑定到人，claim 后才产生 Assignment 与租约。

Demand
需求

业务诉求与审计的根对象；状态机与模板版本一起固定。

submitted → in_progress → review → done
Stage / StageRun
阶段 / 阶段运行

模板声明输入、执行器与门禁；运行记录 attempt、工件与耗时。

pending → ready → running → waiting_human → done
Task
任务

可领取的工作单元；可空 workspaceBinding 决定通用箱还是按目录派发。

pending → claimed → in_progress → completed
Assignment
指派

任务与执行器的一次绑定；60s 租约、20s 续约，过期回池。

active → completed | released | expired
Artifact
工件

不可变版本；上游更新使下游 stale 并阻断推进。

draft → generated → in_review → approved
Gate / Approval
门禁 / 审批

唯一的人工卡点；一次一个明确决策，绑定工件版本。

pending → approved | rejected | withdrawn | expired
REST 写操作 + Idempotency-Key WS 摘要推送 + seq 补齐 Lease 60s / 续约 20s Event append-only + resync Context task/<id>/context.md
支撑对象 执行器 · Hook · 事件 运行时属性 Presence · Lease · Workspace

04 · 主流程

一条需求，六个阶段，五道门禁

人只在门禁出现；其余阶段按依赖自动推进。默认 3 阶段模板：分析 G1 → 开发 G3 → 验收归档 G4。

06 · PDO 迁移

不 1:1 平移：9 个动作 → 6 个阶段

把“点 AI 生成 + 人工确认”重构成阶段执行 + 门禁；中间系统只留 Hook 入口。

  • 点 AI 生成开发说明生成
  • 点 AI 生成开发生成

08 · 安全

凭据可用不可见

控制平面被攻破，也不等于开发者机器被接管；模型上下文里永远没有凭据。

本地

SAP / SSO 凭据✓abap-cli · git
模型上下文✕凭据

写操作在本地确认；服务端只收到命令结果与工件摘要。

服务端

BYOK Key✓secret manager
客户/需求数据✓BYOK 模型

自部署或已签安全协议；Key 不入库、不下发客户端、不写日志。

审计

事件日志append-only
工件版本不可变审批

每次状态变化可还原：谁、何时、基于什么、改了什么。

提示注入 任务文本视为数据，不是指令 写操作 人工确认 + allowedSystems 白名单 权限 v1 不建模；只记录操作人 SSO web 走 ICF 登录；服务账号独立
